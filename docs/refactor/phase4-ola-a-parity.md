## Partial canary routing facts

The recorded source `142b6e0` configures the first canary domain as QR creation, help, and system status. The evidence record says the canary is deployed for one private chat, has no groups, reports health 200, keeps proactive work disabled, and has a pending human QR/help/status walk. It also records no production `bot.db` modification and zero-message runtime probe; those are operational checks, not feature parity evidence.

`V2_CANARY_FEATURES` controls which incoming text requests `phase4CanaryRuntime` may claim. The runtime's default is `qr,help,system-info`; the matcher returns false for empty text, explicitly leaves QR read/quoted/media requests to legacy, and declines the listed later-wave business domains. The generic bare greeting `hola` has no matching Wave A intent, so it remains legacy by matcher inspection. Direct tests assert bare media and quoted/read QR stay legacy in [tests/unit/refactor/phase4CanaryRuntime.test.js](../../tests/unit/refactor/phase4CanaryRuntime.test.js); the generic greeting result is source-derived rather than a dedicated assertion there.

Help has its own active-feature filter: [tests/unit/v2/features/minimal.test.js](../../tests/unit/v2/features/minimal.test.js) verifies a feature with `enabled: false` is omitted. In addition, the deployed `142b6e0` runtime composition filters `media.features` by `config.V2_CANARY_FEATURES` before creating the app (see `src/v2/composition/runtime.js`, line 131 in that commit). With the recorded `qr,help,system-info` allowlist, only those media features are registered alongside the always-present help and system-info features. The focused offline contract [tests/unit/v2/composition/canaryHelp.test.js](../../tests/unit/v2/composition/canaryHelp.test.js) verifies the runtime feature subset and confirms help omits documents, sticker, voice, and transcription commands; the test uses fake dependencies and performs no provider requests.

The specific canary tests and implementation are [tests/unit/refactor/phase4CanaryRuntime.test.js](../../tests/unit/refactor/phase4CanaryRuntime.test.js), [src/services/phase4CanaryRuntime.js](../../src/services/phase4CanaryRuntime.js), [src/v2/features/help/handler.js](../../src/v2/features/help/handler.js), and [src/v2/composition/runtime.js](../../src/v2/composition/runtime.js). Runtime ownership declines `--to`/destination requests except inside an explicit literal QR payload; legacy remains responsible for addressing and quoted QR behavior.

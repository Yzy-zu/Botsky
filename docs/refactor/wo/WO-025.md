# WO-025 / Fase 2 / Auditoría y corrección del límite IA

Objetivo: reproducir y corregir fallos de validación de esquema, salida del proveedor y deadline dentro del adaptador IA.

Archivos autorizados: `src/v2/adapters/ai/**`, `tests/contract/ai*.test.js`, este documento. No config/package/core/features/legacy/PROGRESS ni producción. Sin commits.

Insumos: fuente actual WO019, contratos de dominio y veinte pruebas contractuales previas. Configuración, HTTP y reloj exclusivamente falsos; no proveedores, claves ni costes reales.

## Evidencia antes de corregir

Las cinco pruebas iniciales nuevas fallaron sobre la fuente existente (0 pass / 5 fail):

1. `required:'action'`, reglas malformadas y keywords no soportadas en propiedades opcionales ausentes daban validación positiva. La evaluación solo visitaba el schema de propiedades presentes.
2. Un objeto con datos adicionales sin schema admitía profundidad arbitraria, Infinity y objetos Date. El límite de profundidad solo se aplicaba a ramas con regla recorrida.
3. `generate().data.text` incluía texto de partes `thought:true`; la eliminación de thoughts ocurría después de componer text. Además `data.parts` conservaba metadata arbitraria del proveedor.
4. Una parte `{text:123}` acompañada por texto válido cruzaba la frontera pública pese al contrato text:string.
5. Una respuesta a `clock.now()===deadline` aún retornaba éxito: comparación `>` en vez de `>=`.

Estas son reproducciones del adaptador v2 aislado, no diagnósticos de producción.

## Cambios

- `schema.js`: validar el árbol completo de schema antes de evaluar datos, incluidas ramas opcionales ausentes. Rechazar keyword desconocida y tipos incorrectos de required/items/additionalProperties/bounds/annotations. `additionalProperties` soporta boolean en este subset; schemas como valor permanecen explícitamente no soportados. Aplicadores sin type respetan la semántica de JSON Schema sobre el tipo de dato correspondiente. Enum compara objetos sin depender del orden de miembros.
- `isBoundedJson`: árbol entero, incluidos datos sin regla; máximo16 niveles,10000 nodos y1048576 caracteres agregados de strings/keys. Rechaza ciclos, getters, arrays dispersos, objetos no JSON, números no finitos y keys inseguras `__proto__`/`prototype`/`constructor`. No ejecuta getters. Límites técnicos para schema y argumentos/respuestas estructurados; no son límites de contenido conversacional impuestos al usuario.
- `request.js`: schema de salida y tools parameters deben ser soportados antes de HTTP. Campos de request/budget/message/tool/inlineData/functionCall/functionResponse cerrados al contrato del dominio; metadata inesperada no sale al proveedor. Datos de functionCall/response deben ser JSON acotado. Tokens deben ser enteros seguros.
- `response.js`: normalizar las partes visibles a variantes de dominio nuevas; quitar thoughts antes de text/toolCalls y copiar únicamente text/inlineData/functionCall/functionResponse. Rechazar formas inválidas/variantes mezcladas, args no JSON acotado, número excesivo de partes y flags thought malformados. Metadata y referencias mutables crudas del proveedor no entran a la salida pública.
- `failures.js`: partes null/primitivas no causan TypeError clasificado como red; producen invalid_response/bad_output seguro antes de filtrado.
- `index.js`: usar partes normalizadas para texto y propuestas de herramientas; mantener autorización por declaraciones/schema, fallback y ABI raw de callGemini separado. Plazo vencido incluye el instante exacto. No introduce ejecución de herramientas.

La API pública sigue siendo generate(LLMRequest)→LLMResult; el contrato de core no cambió. Helpers nuevos isSupportedSchema/isBoundedJson/normalizeParts son internos al adapter. callGemini conserva content/metadata raw del proveedor para compatibilidad de ABI; generate es la frontera validada del dominio.

## Riesgos y límites

Subset JSON Schema sigue sin $ref/oneOf/pattern ni schemas como additionalProperties: ahora no puede aceptar silenciosamente esas reglas por falta de datos. Un futuro schema que use esas capacidades debe ampliarse en una WO explícita. Límites JSON y claves reservadas requieren que composición genere schemas técnicos seguros; pueden rechazar formatos extensos o nombres reservados que nunca estuvieron cubiertos por el contrato validado.

HTTP port todavía debe cumplir el timeout restante: esta WO evita éxito tras vencimiento y nuevos intentos tardíos, pero no crea un timer de cancelación si el transporte ignora su propio timeout. Cualquier metadata de continuidad del proveedor necesaria para un tool bridge futuro debe viajar por ABI provider-controlado y explícito, no como campo arbitrario de LLMData.

# WO-019 / Fase 2 / Adaptadores IA y contrato LLM

Objetivo: separar transporte/protocolo Gemini/Groq, pool y fallas del núcleo legacy, sin ejecutar herramientas ni cargar configuración de producción.

Archivos autorizados: `src/v2/adapters/ai/**`, `tests/contract/ai*.test.js`, este documento. No main/config/package/PROGRESS, legacy ni otros adapters. Sin commits.

Insumos leídos: ai.js completo por segmentos, aiConfig, aiFailure, generationSettings, conversationStyle; ai_pool y aiDiagnostics y pruebas de voz/estilo relevantes. Dominio/ports lo define el maestro; llm.port.js solo reexporta ese archivo, sin contrato paralelo.

API principal: `createAiAdapter({config:()=>typedConfig,persona?:()=>settings,clock,http:{post},maxConcurrent?})` → `generate(LLMRequest)`, callGemini(ProviderRequest), callGroq(ProviderRequest), pool/breakers y consultas de claves/disponibilidad. Sin env, archivos, red ni timers al importar/crear; HTTP y configuración son puertos inyectados.

`generate` valida formas de messages/parts/tools/budget antes de invocar transporte y devuelve LLMResult discriminado. Convierte roles system/user/assistant/tool y herramientas neutrales en formato de proveedor. Preserva texto, native inline PDF/imagen, functionCall/functionResponse y extracción de toolCalls, sin ejecutar nada. Groq correlaciona IDs de llamadas/respuestas durante traducción. Salida de schema se valida localmente y se rechaza si truncada; subset JSON Schema explícito y acotado, keywords no soportadas fallan cerrado. Executor futuro decide permisos; adapter no concede acceso.

Deadline: uno por tarea `clock.now()+budget.timeoutMs`; los timeouts de cada intento/reintento y respaldo se reducen al tiempo restante. No empieza un intento vencido y rechaza respuesta tardía. El HTTP port debe respetar `options.timeout`: sin real timers ni cancelación transport propia en estos módulos. Presupuesto tokens es techo y perfiles no lo aumentan.

Comportamientos preservados: orden canónico 1/2/3 + claves dinámicas numeradas + CSV opcional/dedupe; prioridad panel geminiKeys/groqKey; rotación; 429 backoff15/30/60/120s; 403cooldown120s, 5xx4s, red3s; 400 no cambia claves; una repetición de timeout acotada por deadline, PDF con35s como techo de retry directo; parámetros modelo/header/safetySettings; Groq max_completion_tokens y flags OSS include_reasoning/reasoning_effort; content/metadata ABI; safety explícito no habilita fallback; vacío/malformed pueden respaldo; PDF/vision jamás se degrada a respuesta ciega de Groq.

Refuerzos solicitados por el maestro: cooldown es efectivo incluso con única clave o todas enfriándose (legacy las reusaba);401 deshabilita clave hasta reset/recambio; breaker60s con umbral3, half-open de una sola prueba y máximo4 solicitudes concurrentes por proveedor (configurable). Éxitos antiguos en vuelo no cierran un breaker abierto por otra generación. No costos ni proveedores reales en verificación.

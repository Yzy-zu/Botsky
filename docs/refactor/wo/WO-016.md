# WO-016 / Fase 1 / Tooling, integración y gate

Responsable: maestro. Trabajo en worktree refactor/v2; sin activar v2 ni
cambiar configuración o fuentes de producción durante esta fase.

Entregables: tsconfig.v2.json, ESLint con regla propia contra Map/Set global,
auditor de dependencias AST, inventario/generador de env, runner de cobertura
Node, tests negativos del tooling, package/lock y workflow CI.

El chequeo de tipos es estricto y abarca src/v2. El auditor rechaza ciclos,
imports a legacy, features→adapters, cruces de familias de adaptadores,
dependencias inversas, imports dinámicos no auditables y lecturas de env fuera
de config. El lint rechaza colecciones globales incluso bajo Object.freeze,
que no vuelve inmutable su contenido. No requiere dependency-cruiser: script
propio permitido en §11, probado con ejemplos que deben fallar.

El inventario AST documenta env estáticas JS/CJS, aliases/destructuring y
brackets; incluye auxiliares Python y el patrón dinámico Gemini. No lee .env.
El schema también declara settings futuros, aliases e infraestructura.
env:check exige igualdad exacta con el generador y no deja env usadas sin
documentar. Las variables shell del runner fueron revisadas en WO013.

coverage:v2 ejecuta unit v2/tooling y comprueba exit del runner además del
reporte. Exige >=90% líneas por cada módulo crítico de config, TTL, queue y
scheduler; archivos ausentes también fallan. Se elimina NODE_V8_COVERAGE
heredado: ponerlo vacío en Node20 provoca un exit fallido y no equivale a
desactivarlo. No hay flags para omitir umbrales.

Dependencias de desarrollo fijadas: TypeScript5.9.3, ESLint10.12.0,
@types/node20.19.43; engine>=20.19 por compatibilidad del tooling. Node host
20.20.2. npm ci --ignore-scripts reproducido; dependencias productivas y sus
integridades no cambiaron frente a 99f01bf. Audit conserva 10 vulnerabilidades
legacy conocidas; no se aplicó force-fix. La CI usa el mismo verify, sin
credenciales ni servicios de negocio. No se ejecutó CI remoto ni se hizo push.

Integración: limpieza comparte ejecuciones manual/ticker; pruebas de crypto
leen y escriben tokens con el módulo legacy real, que es puro. Typeguards de
InboundEvent rechazan null/primitivos en campos objeto. Los tests usan
FakeClock; SystemClock se prueba con timers estándar mockeados.

Evidencia final en phase1-evidence.md. Suite legacy permanece separada con
baseline rojo documentado; verify no afirma reparar los 187 fallos previos.

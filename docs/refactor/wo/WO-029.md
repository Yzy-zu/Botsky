Detalle de cambios:

- Mensaje valida identidad antes de consultar IA/redactar/resolver otro chat, manteniendo la autorización central existente. Args estructurados siguen prioritarios; forma explícita legacy `[contacto,...recado]` funciona. Grupo principal conserva su JID existente; nombres desconocidos mantienen aclaración/no envío. No se configura grupo nuevo ni se aprende de textos arbitrarios.
- executeTool no confía en `context.isAdmin` ni `context.senderJid`: obtiene emisor desde from y metadata de WhatsApp y llama auth. Permisos admin existentes se conservan; claims nunca amplían acceso. Ausencia de chat produce error antes de servicios/SQLite. Args/context arrays a nivel raíz se rechazan; datos JSON se copian por descriptors a objetos sin prototipo. Accessors, circular, BigInt, funciones anidadas, valores no finitos/profundidad excesiva fallan sin ejecutar getter o herramienta. No logging de args personales ni JSON.stringify fuera try. Error externo queda `{success:false,error}`; lectura defensiva del mensaje de error no evalúa accessors.
- Wrapper opcional de telemetry mantiene `process` inexistente compatible con VM. Antes de trackTool toma snapshots seguros; malformedargs pasa al error de executeTool sin exponer getters a telemetry. Cache de Promise de operación garantiza que si tracker inicia la operación y luego lanza, fallback no la ejecuta de nuevo. Regresión VM comprueba exactamente una entrega y una confirmación; tracker/IO/servicios ficticios.
- Registry conserva aliases/tier/ejecución y mutación pública válidos. Rechaza name/context/from/parsed de tipo inválido; normaliza args/flags opcionales de un objeto parcial, aceptando `{args:[]}` sin flags. Preserva la referencia parsed/flags válida que música modifica a formatoMP3. No se atrapan silenciosamente los errores de negocio de un handler válido para fingir éxito.

Actualización de harness/assertions: testmensaje carga módulos reales dentro de VMs con lista explícita de dependencias y rechaza imports inesperados. Modelo, transporte, DB afinidades y groupInfo son fakes; auth es módulo real evaluado con ALLOWED_NUMBERS_ADMIN ficticio. IDs/contactos telefónicos viejos se sustituyeron por números ficticios1999555*. El caso admin aporta metadata del emisor, el caso noadmin también. Confirmación se busca sin distinguir mayúsculas porque fuente real dice `Va, ya le escribí...`; se conserva exigir destinatario, confirmación y contenido, sin alterar mensajes de producto. Las validaciones de montos en toolRegistryRobustness usan contexto ficticio válido para probar realmente los argumentos; no se baja la aserción de validación por un fallo de contexto ausente.

## Ampliación delegada BF120

Se modificaron únicamente: ayuda, convertir, descargar, difusión, documentos (cinco handlers), drive, efectos, lore, maicra, niveles (cuatro handlers), notas, QR, transcribir, voz y sistema. Inputs válidos conservan aliases, handlers, permisos y ejecución. Top omite filas con jid nulo/no-string para evitar crash y menciones inválidas; no modifica ni elimina filas de SQLite.

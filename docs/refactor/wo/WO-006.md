# WO-006 / Fase 0 / Anonimizador offline de webhooks

Objetivo: preparar una herramienta local que transforme payloads de webhook previamente obtenidos en envelopes sintéticos sin conservar secretos ni contenido personal.

Archivos permitidos: `scripts/refactor/anonymize-webhook.cjs`, `tests/unit/refactor/anonymize-webhook.test.js`, `docs/refactor/wo/WO-006.md`. No se modificaron fixtures existentes, aplicación, producción, logs, `.env` ni bases de datos. No se realizaron capturas ni commits.

Insumos: formato de `messages.upsert` y campos esenciales consumidos por el normalizador legacy. Contratos: función pura `anonymizeWebhook(input)` y CLI JSON stdin → JSON stdout; allowlist estricta; identidad e IDs sintetizados con contadores, sin hashes ni estado persistente.

Uso desde la raíz, una vez que exista un payload obtenido de forma controlada:

```sh
node scripts/refactor/anonymize-webhook.cjs < /ruta/privada/captura.json > /ruta/revision/captura-anonimizada.json
node --test tests/unit/refactor/anonymize-webhook.test.js
```

La entrada debe ser un envelope `{event:"messages.upsert", data:{...}}` o un array de envelopes relacionados. Los mappings se reinician en cada llamada. Para conservar relaciones entre salientes, citas, reacciones, votos y mensajes entrantes, pasar el conjunto en **un mismo array**, incluyendo los salientes necesarios. Una llamada independiente no comparte IDs con otra. La herramienta no lee archivos de captura por su cuenta; solo stdin. No imprime payloads originales ni detalles del error en stderr.

Se preservan estructura de mensaje conocida, flags `fromMe`/`ptt`, JIDs de grupo/LID/teléfono por sufijo sintético, `participantAlt`, `remoteJidAlt`, `participantPn` y `senderPn`, identidad citada, `stanzaId`, menciones, referencias a IDs y MIME de una lista pública cerrada. Textos idénticos permanecen idénticos entre sí tras transformarse; citas de humano y bot mantienen identidades/IDs distintos. La herramienta no decide quién es bot: el harness debe identificarlo a partir del saliente o de la configuración ficticia.

Nombres, texto, captions, filenames, JIDs, IDs, URLs e instancia se reemplazan. Se omiten headers, API keys, campos desconocidos, bytes/base64, claves de medios, thumbnails, rutas directas, metadata arbitraria, fechas/tamaños/duración reales y votos cifrados. Reacciones públicas conocidas, como 👍, se conservan. Los wrappers conocidos y quotes se recorren hasta profundidad 8; estructuras más profundas se truncan. No se copian propiedades arbitrarias de objetos.

Límites: reemplazar texto elimina prefijos/comandos, nombres de menú, wake words y menciones textuales, aunque preserve `mentionedJid`. Los votos se conservan solo si ya vienen decodificados y sus nombres se sustituyen; no se prueba el menú legacy con ese contenido. Los medios quedan sin claves ni datos y URLs `.invalid`: no son descargables. Los sufijos LID se preservan pero los detalles de dispositivo no. Formatos desconocidos quedan sin contenido; requieren revisión del allowlist antes de usarlos. No produce equivalencia semántica ni replay operativo completo. Para escenarios, sustituir posteriormente los textos generados por contenido ficticio del mismo tipo que se desea probar: prefijo `/estado`, wake word `Botsky`, selección `2`, etc.; conservar relaciones de igualdad deliberadas entre citas. Registrar la procedencia del envelope como `real-anonymized` **solo si provino efectivamente de una captura**, separándola de la procedencia sintética de los contenidos sustituidos. Los fixtures existentes puramente sintéticos conservan esa procedencia. Revisar manualmente la salida antes de incorporarla al repo; registrar aparte la procedencia y el formato/version de Evolution sin datos personales.

Validación ejecutada: `node --test tests/unit/refactor/anonymize-webhook.test.js` → **6 pass / 0 fail**. Cobertura de fugas de secretos/PII, inmutabilidad, coherencia bot/cita/mención/ID, humano con mismo texto, LID alternativo, reacciones/polls/wrappers, unknown fields, mappings deterministas y CLI con error que no refleja entrada. Tests importan únicamente esta herramienta y módulos estándar de Node; no cargan aplicación, entorno, SQLite ni servicios.

Estado: herramienta y validación terminadas. **La captura real y la evidencia operativa de Gate 0 siguen pendientes**. Esta WO habilita anonimización offline; no acredita que se hayan capturado webhooks reales.

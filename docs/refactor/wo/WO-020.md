# WO-020 / Fase 2 / Puertos, integración y gate

Responsable: maestro. Implementación en worktree `refactor/v2`, sin activar v2,
reiniciar producción o migrar su SQLite durante Fase2.

Entregables: `domain/ports.js` como contrato único de Messenger/LLM/repos;
`tests/contract/ports-typecheck.js` comprueba compatibilidad estructural de las
factories sin ejecutarlas. No definiciones divergentes en adapters/ai/llm.port.
Tipos estrictos incluyen módulos v2 y ese chequeo. `verify` ahora incluye todos
los contratos, con SQLite real/temporal y HTTP local/fakes; CI prepara binding.

CLI de native tables v2 requiere explícitamente ambos paths, reemplaza archivo
solo tras validar bundle completo, conserva modo/idempotencia y rechaza
symlinks. Test operator usa únicamente fixture temporal, sin parche productivo.

El runner migrations rechaza historial retroactivo antes de respaldo/mutación;
el test prueba que no se crean tabla ni backup. SQLite backup usa VACUUM INTO,
integrity y checksum; read/write v1 real probado con env controlado. Esquema000
completo 24tablas13indexes4ALTER. Bytes SQL originales conservados (incluyen
espacios del legacy); no modificar por estilo un checksum versionado.

Revisión mediante agentes: WO025 valida JSON/esquemas en todas sus ramas, limita
profundidad/tamaño y elimina thoughts/metadata de salida pública; WO026 rechaza
base64 inválido y bloquea reenvío/fallback si hay evidencia de ACK. Ningún error
retiene ID/body privado para esa decisión, solo booleano técnico.

Regresión legacy aislada conserva imagen/entorno del baseline y recompila driver
solo en copia del contenedor. `compare-legacy.cjs` verifica SHA del TAP original,
cuenta fallos por título con multiplicidad y excluye agregadores de suite. Los
tests negativos prueban que duplicar un fallo o añadir uno nuevo no se oculta.
El resultado completo, no un TAP parcial, sustenta F2-E001.

El cliente delegó el criterio al responder “lo q tu creas mejor papu” a la
pregunta sobre excepción/deuda. Maestro elige F2-E001: deuda previa por función
hasta su migración, todos los nuevos contratos/verificaciones verdes y cero
fallos nuevos. No se borra test ni se llama verde a la suite legacy. Antes de
cada ola y del cutover se reevalúa la deuda; este permiso no autoriza DROP.

`npm run verify:phase2` ejecuta verify y gate read-only con evidencia de los tres
adaptadores/schema/backup/compatibilidad/regresión. Su test exige rechazo de
baseline rojo sin autorización, de una regresión nueva o de contratos omitidos.
El reporte reconoce que los documentos son atestación de ejecución, no una
prueba independiente de que ocurrió. Evidencia en phase2-evidence.json/.md.

WO024 es tooling opcional para revalidar deuda en un entorno más completo, nunca
reemplaza la comparación con baseline ni sus hashes. Lecturas de librería son
solo código externo y fixtures nuevos; no copias de datos/configuración reales.

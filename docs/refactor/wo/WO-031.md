# WO-031 / Fase 3 / Políticas puras

Objetivo: implementar addressing, access, response, attachment y proactive según §6 del plan, sin prompts para decidir permisos ni efectos de servicios.

Scope: `src/v2/policies/{addressing,response,proactive,attachment,access}.policy.js`, `tests/unit/v2/policies/*.test.js`, este documento. No cambios a composición/pipeline/adapters/config/PROGRESS ni commits/despliegue. Inputs son eventos/metadata/snapshots ya normalizados; sin clocks globales, env, red, DB, timers, Map/Set global ni mutación de inputs.

Contratos compartidos: eventos/reply desde domain; Session/Attachment/Roles desde `pipeline/contracts.js`. `AddressingMeta` extiende AddressingMetadata con `now?:number,botJid?:string`; metadata de sesión/adjunto debe venir filtrada por **chat+owner** desde Context. El contrato shared no contiene chatId y la policy no inventa lectura de caches. Las policies usan options.now/meta.now/event.receivedAt, nunca Date.now.

- `addressingPolicy(event,meta,options)` → AddressingDecision. Options botJid/prefixes/wakeWords/sessionGroupRelaxed/now. Own messages ignoran; privado responde. Grupo: mención exacta del bot, quoted.isFromBot probado, prefijo con comando, wake-word Unicode exacta botsky/botsito (palabra genérica bot prohibida incluso si la pasan en configuración), continuación de sesión dirigida o instrucción citando adjunto propio vigente. '#3' sin continuación válida no se convierte en comando genérico por prefijo. Sesión requiere owner/expiry, selección `2`/`el 2`/`#3`, selectionValid no explícitamente falso y result quote correcto o mención; relaxed requiere flag explícito y edad0≤t<90000ms. Numeric bounds son del productor de la sesión/Executor, no inferidos por la policy. Un quote a otro mensaje del bot admite chat por §6.1 pero no addressedBy=session: Router debe respetar esa diferencia. Exception de juego: group+airdropActive+yoo responde con reason active-airdrop-claim, sin addressedBy inventado; el manifest/router acota ejecución, no dispara proactividad ni chat largo por sí solo.
- `accessPolicy({senderJid,chatId,isGroup,roles,requiredAccess,scope})` → allow/reason. Jerarquía public<member<admin<owner, lists exactas; roles owners/admins y members opcionales de snapshots. Scope group/private declarativo. Sender groupJid nunca obtiene privilegios. normalizeJid elimina device, canoniza PN521/52/10dígitos como auth; namespaces LID/grupo se preservan, no comparación substring, no crossnamespacegrant. Domains desconocidos, múltiples@ y strings inválidos se rechazan. Gate/Context debe poblar members cuando command requiere member; esta policy no concede membership por el nombre de un grupo.
- `responsePolicy(reply,{isGroup,detailRequested,allowLong,privateMaxChars=600,groupMaxChars=350,maxStatusLines=6,status,recentReplies,variationAttempted})` → Reply nuevo. Presupuesto agregado de texto/captions; límite por Unicode codepoints, truncación con elipsis y sin cortar surrogate. Estado≤6líneas salvo detalle/allowLong. No se limita contenido largo expresamente solicitado/autorizado por feature. Solo elimina marcadores terminal legacy de error; no inventa diagnóstico ni expone error raw. Composer traduce taxonomía a mensaje+siguiente paso. Repetición helper puro `responseRepetition(reply,recentReplies,variationAttempted)` → none/vary-once/fallback: Composer puede pedir **una** variación al LLM y reconsultar con variationAttempted:true; si sigue igual aplica plantilla breve. Policy no llama LLM y no genera retry loops. Poll options se copian; media/replyTo/ephemeral metadata preservadas.
- `attachmentPolicy(event,meta)` → `{cache,suggest?,followupAllowed}`. Todo media actual imagen/video/audio/documento/sticker con ref se indica cache; almacenamiento/TTL10min/chat+owner son del Context. Bare privado imagen/video/audio/documento obtiene reacción👀 y **una** sugerencia corta≤3acciones; grupo silencio, sticker sin sugerencia. Adjunto vigente propio permite instrucción privada corta≤80chars sin quote; grupo requiere quote matching o mention exacta según meta.botJid. No descarga ni genera cadena fantasma; reacción👍/Drive permanece en feature, no se reinterpreta aquí.
- `proactivePolicy({...})` → allow/reason. Global/chatkill switches, opt-in grupo o flagprivado explícito, quota3/día, separación45min, quiet23:00–08:00 America/Mexico_City. now/dailyCount/lastSentAt/timezone vienen inyectados. Frontera08:00 permite,23:00 bloquea; intervalo normal/cruza medianoche. Config inválida, lastsend futuro, zona inexistente fallan cerrados; quietstart=end se trata como silencio todo el día (configambigua no habilita mensajes). Policy no incrementa cuota ni manda nada; Scheduler/Context asumen dueño único.

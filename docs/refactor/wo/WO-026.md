# WO-026 / Fase 2 / Revisión de media y evidencia de entrega Evolution

Objetivo: corregir defectos reproducidos en validación base64 y envíos que ya tienen prueba de entrega, preservando formatos válidos y compatibilidad de firmas.

Scope: adapters/evolution, contracts Evolution y este documento. Cambios concretos: `media.js`, `client.js`, `outbound.js`, `echoGuard.js`, nuevo `tests/contract/evolutionHardening.test.js`. No edits fuera de alcance, globals/env/producción, defaults de producto ni commits. Revisiones y aprobación del maestro: validación canonical y booleano safe de delivery en errores.

Defectos reproducidos antes del arreglo: tests nuevos fallaron por `Missing expected rejection: A=` (download devolvía buffer vacío) y `sentChunks:0` con rechazo native table400 cuyo error contenía `key.id` real de entrega. Decoder de Node acepta padding inválido/trailing bits que no correspondían a los bytes canónicos; el sanitizer descartaba el ID pero también su evidencia, habilitando fallback a texto y posible duplicado.

Cambios:

- Base64 exige contenido tras quitar whitespace, alfabeto válido, padding compatible con grupos de4 y representación canonical de bits tras decodificación. `A=`, `A==`, `AA=`, `AAAA==`, `AB==`, `AAB=` y contenido vacío/whitespace/dataURI vacío se rechazan con error legible. Permanecen válidos dataURI normal y base64 canonical con padding, sin padding y whitespace permitido. Límite de bytes sigue antes de la decodificación; buffer canonical se reutiliza, sin segunda copia de download.
- Error de Evolution extrae prueba de `key.id` string no vacío en root, `data.key` o `response.key` y conserva **únicamente booleano** `deliveryAcknowledged` público/tipado y en response.data sanitizado. No almacena ID, JID, cuerpo ni tokens originales. Valores vacíos, whitespace, números/null no cuentan como prueba. La propiedad no se inventa por status/mensaje.
- EchoGuard añade `delivered` independiente de `echoed`: ACK normal o error con prueba safe permiten history única y bloqueo de fallback. `sentChunks`/partialDelivery y media parcial usan evidencia de entrega, sin fingir que ocurrió un webhook eco. Fallos definitivos sin delivery continúan limpiando cache/fallback como antes.
- withRetry corta inmediatamente cualquier error con deliveryAcknowledged incluso500; un POST ya enviado no se repite. Las operaciones legacy que reintentan errores sin prueba mantienen su contrato.
- Límites MB de constructor comprueban que su conversión a bytes sea representable como entero seguro. Se rechaza overflow finito (`1e300`) antes de IO/red; defaults64/200MiB permanecen.

Revisión sin cambio de política: EchoGuard consume un webhook propio **después de que ingest haya verificado fromMe**. Su API histórica solo recibe chatId/messageId/text y no constituye addressing ni clasificador de quotes. Una cita humana con texto idéntico después de ACK e ID propio diferente no se consume; correlación pre-ACK por texto sigue limitada a sends pendientes y caller debe filtrar fromMe. S13 integral queda para pipeline/ingest; esta WO no amplía permisos ni decide quotes por contenido.

Constructor media/echo inválido y counterlímites tienen contratos explícitos. No nuevas anotaciones blanket-any; extracción de error trabaja sobre unknown con Record y validación. Fakes de HTTP/IO/FakeClock aíslan todos los tests nuevos, sin timers reales de espera.

43 resultados fallaron antes de evaluar contratos porque `terminal.js:350–370` solicita UID/GID1002 mientras `cap-drop ALL` impide setuid/setgid. `agent.test.js:19–146`, `terminal.test.js:20–226` y `audit_fixes.test.js:58–110` exigen shell/timeout/truncado reales; simular todos sus resultados ocultaría defectos.

Node padre root para leer fixture de configuración; subprocess del módulo baja a1002. `--cap-drop ALL --cap-add SETUID --cap-add SETGID` **solo dentro del contenedor**; sin privileged/SYS_ADMIN, socket Docker, red ni mount writable del host. Source mount readonly; trabajar en copia desechable dentro del contenedor.
2. Directorio de trabajo `/home/petrov/botsky`, home `/home/petrov`, tmp writable para UID1002. Inicializar un `.git` temporal en esa copia, con ownership1002/safe-directory correcto: `audit_fixes:108` exige git status, no basta copiar src/test sin .git. Configuración/DB nuevas exclusivamente de fixture.
3. `.env` **falso** generado dentro del contenedor, propiedad root y chmod0600. Padre lee dotenv; UID1002 obtiene Permission denied al `cat`, como exige `audit_fixes:76–84`. Sin archivo el error sería ENOENT y test rojo; chmod0666 haría falsa la protección. No copiar .env existente.
4. No instalar Bubblewrap en esta imagen: `terminal.js:312` lo detecta por existencia y activa mount namespaces (`--bind / /`) que requieren más capacidades. Este harness ejercita el fallback legacy de separación de usuario/permisos; no acredita aislamiento bwrap. Un contrato bwrap real necesita suite/entorno específico futuro, sin relajar contenedor general.
5. `id`, bash, node, procps (`uptime/free/pgrep`), coreutils (`df/base64`) y git reales. Mantener pruebas timeout/subárbol/truncado; nunca correr estos comandos mediante módulo legacy en el VPS.

No montar Docker real para aprobar. Opción de test correcta: fixture CLI `docker` que registre invocación/retorne listado sintético, rotulando explícitamente esa prueba como ejecución de comando contra backend fake.

# WO-034 / Fase 3 / Observer de sombra acotado y privado

Objetivo: observar decisiones v1/v2 sin bloquear delivery legacy ni ejecutar negocio v2, con counters/checkpoints operativos y un puerto Messenger que detecta IO accidental.

Scope: `src/v2/platform/shadow.js`, `tests/unit/v2/shadow.test.js`, este documento. Sin cambios a pipeline/flags/webhook/main/config/PROGRESS, env ni producción; no commits/despliegue. Imports de contratos/Clock son JSDoc; al importar no se construyen servicios ni timers/Map/Set globales.

API:

```js
createShadowObserver({
    clock,
    decideOnly: async (raw, signal) => pipeline.decideOnly(raw),
    writeDiff: async diff => dedicatedSink.append(JSON.stringify(diff) + '\n'),
    maxPending: 32,
    timeoutMs: 30000,
    allowedFeatures: ['help', 'system-info'],
    allowedReasons: [],
    initialCheckpoint: undefined
})
```

La lista adicional de reasons/features es **configuración confiable del composition root**, nunca tomada del payload ni del resultado del modelo. El sink es inyectado y dedicado exclusivamente a diffs/telemetría sombra; el módulo no abre archivos ni elige una DB productiva. El ejemplo no se ejecutó ni configura un sink concreto; el maestro provee almacenamiento y límites/rotación operativa al activar flags.

- `observe(raw,v1DecisionPromiseOrSnapshot)` devuelve booleano de admisión inmediato; los jobs se lanzan en microtask y nunca espera v1 a v2. Queue y ejecución única suman≤maxPending; saturación o stop descartan/adicionan dropped. Cada v1 Promise recibe rejection handler incluso cuando se descarta un evento, evitando unhandled rejection. Raw existe únicamente en memoria temporal hasta ejecutar/descartar, nunca entra en sink/checkpoint.
- `stats()` devuelve startedAt/observedUntil UTCepochms, observed/processed/exceptions/dropped, pending/active, elapsedMs y previousObservedUntil. Timeout cuenta excepción, solicita abort, pero no libera el slot hasta terminar realmente decideOnly/v1Promise/sink; no se finge cancelación ni se aumenta concurrencia. Si una dependencia ignora signal y jamás termina, pending permanece, nuevas admisiones pueden descartarse y flush/dispose esperan esa ejecución real.
- `stop()` rechaza admisiones nuevas, elimina referencias raw pendientes y solicita abort del activo; no interrumpe negocio legacy. Congela observedUntil/elapsedMs para que tiempo detenido no aparezca como sombra observada. `flush()` espera cola/ejecución; `dispose()` stop+flush. Los jobs activos admitidos pueden terminar escribiendo su diff sanitizado después de stop.
- `checkpoint()` contiene solamente `{startedAt,observedUntil,observed,processed,exceptions,dropped}`. InitialCheckpoint valida tiempos finitos/orden/hasta ahora, counters enteros≥0 y processed≤observed. Seed conserva totals históricos y previousObservedUntil; **startedAt del segmento continuo siempre se reinicia a now en la instancia nueva**. Jobs de un proceso anterior no se reconstruyen: checkpoint es counters, no cola duradera ni historial de mensajes. No se suman periodos discontinuos para declarar24h sin restart.

Diff output cerrado:

```js
{
    v1_decision: { kind, respond?, via?, feature?, reason },
    v2_decision: { kind, respond?, via?, feature?, reason },
    category: 'same' | 'v2-more' | 'v2-less' | 'changed' | 'unknown',
    observedAt: epochMs
}
```

Kind/via/reason se limitan a vocabulario estático conocido; feature solo lista confiable. Se toma Decision anidada de PipelineResult y addressing.respond/reason cuando existen. Unknown reason se escribe como unknown, y kind desconocido fuerza categoryunknown: no se inventa cuál fue la decisión legacy. Boolrespond se copia solo si es booleano explícito; no se infiere de textos o prefix de usuario. Categories more/less requieren evidencia booleana contraria, no conteos por substring. Getter/Proxy field access se maneja por descriptors, sin ejecutar accessors para extraer decisiones.

Nunca se copian event/raw/args/name/text/reply/JID/messageId/correlationId/key/token/stack ni errores arbitrarios. Feature/reason extensibles solo se añaden por código de composición confiable. Las excepciones v1/v2/sink se agregan como counters, sin imprimir error ni datos. Unitprivacy injecta todos esos datos y prueba ausencia de PRIVATE_* en JSONdel sink.

`createNullMessenger()` implementa todos los métodos de Messenger: sendText/sendMedia/sendVoice/sendSticker/react/typing/delete/edit/groupInfo. **Lanza SHADOW_IO**, no retorna éxito silencioso. Esto permite detectar Composer/Executor/IO accidental; no convierte el resto de puertos de negocio en seguros por sí mismo. El composition root debe entregar una pipeline independiente con decideOnly que no ejecuta Executor/Composer/passives, repos de lectura/snapshots, fakes/LLMbudget y almacenamiento sombra propio. El observer recibe función decideOnly inyectada: no puede demostrar por inspección que una función arbitraria no escriba negocio. La prueba de cero writes/shell/passives corresponde al harness del pipeline del maestro.

# WO-017 / Fase 2 / Store SQLite, esquema000, repos y recuperación

Estado: implementación y contratos reales verificados; integración/gate global a cargo del maestro.

Archivos permitidos: `src/v2/adapters/store/**`, `tests/contract/store*.test.js`, este documento. Sin legacy/config/package/scripts/PROGRESS, commits, secrets ni acceso a datos productivos.

API `store/index.js`: createDb, migrate, inspectBackup, restoreBackup, createUsersRepo, createConversationRepo. CJS/checkJs strict. Importar cualquiera de los módulos no abre conexiones, crea directorios, registra timers ni carga driver nativo: sqlite3 se requiere solo en open explícito.

`createDb({filename,readonly=false,busyTimeoutMs=5000,cacheSizeKb=64000})`: open/close idempotentes; run(sql,params)→{lastID,changes}, get→row|undefined, all→rows, exec, transaction(async tx=>result), backupTo. Operaciones serializadas con lock y AsyncLocalStorage por instancia, incluidas lectura/escritura/cierre; un trabajo externo no se cuela entre BEGIN IMMEDIATE/COMMIT. Excepción provoca ROLLBACK y se propaga original; fallo adicional de rollback es AggregateError. Contexto ya finalizado no reutiliza lock. No admite transacción anidada ni backup/cierre durante transacción. Writable conserva pragmas legacy WAL/synchronous NORMAL/cache/busy_timeout; readonly no cambia journal_mode.

`migrate(db,{backupPath,migrations?,clock?})`: manifiesto con version/checksum/up, default 000. Valida duplicados/formatos/historia de versiones antes de modificar; si no hay pendiente, no crea respaldo ni tabla. Backup consistente obligatorio antes de cualquier DDL pendiente. Cada up y fila schema_migrations comparten transacción; recheck bajo lock para otro migrador concurrente. No hay contract ni borrados de schema. Esquema de 000 se extrajo **estáticamente** del initializer de `src/services/db.js` (sin importarlo): 24 tablas, 13 índices y cuatro ALTER compatibles (`school_tasks.media_path/due_text/batch_date`, `user_affinities.is_doxxed`) guardados con table_info. No se absorben errores arbitrarios de ALTER.

Semillas: initializer legacy no inserta filas. Estado personality/happy-hour se crea bajo demanda en las funciones respectivas; 000 no inventa singleton ni datos personales. Mantiene ambas tablas personality hasta Fase5 y conserva todas las tablas legacy e índices; no consolida anticipadamente.

Repos mínimos según puertos del maestro: users get/getOrCreate/addXp (normaliza device suffix de JID, XP/level preservados, addXp devuelve levelUp); conversation append(chatId,role,content,name?,timestamp?), recent(chatId,limit?), clear(chatId). Usa Clock inyectado para timestamps. Conserva tabla chat_history y retención 20 por chat; historial por hilo necesita expansión aditiva en fase de pipeline, no se presume resuelto aquí.

Backup: VACUUM INTO parametrizado obtiene snapshot transaccional incluyendo commits WAL, sin copiar `.db` vivo. Reserva destino nuevo/0600; sincroniza archivo; validación readonly real `integrity_check`, versiones y SHA256/size/sqliteVersion/createdAt en manifest sin filas/PII. Rechaza mismo origen, destino existente o sidecars ajenos. Restore solo a ruta nueva/offline, COPYFILE_EXCL + permiso0600 + integrity/checksum; no sobreescribe base ni adopta WAL/shm existente. Para operación real, el dueño debe detener todos los escritores antes de cambiar ruta de producción. Restaurar snapshot pierde escrituras posteriores; no sustituye rollback por flag compatible.

Validación real: `node --test --experimental-test-coverage tests/contract/store.test.js` usa sqlite3@6.0.1 (SQLite3.52.0) reconstruido para host por el maestro, archivos mkdtemp aislados borrados al finalizar. 6/6 contratos verdes: API y errores, interleaving/rollback, inventario completo comparado contra SQL legacy leído como texto, upgrade de schema actual/idempotencia/checksum, DDL+datos+version rollback, segunda conexión con commits concurrentes mientras VACUUM snapshot, restore con users/recordatorio/cooperacha durable activos e integridad real, repos/XP/historial. Source mantiene WAL con escrituras posteriores al snapshot, restore conserva valores anteriores y transacciones de pares completas.

Gate2 global incluye demás adapters y legacy suite; esta WO no afirma cutover/rollback operacional en producción.

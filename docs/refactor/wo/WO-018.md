# WO-018 / Fase 2 / Evolution adapters

Objetivo: portar capacidades Evolution completas a adapters inyectables, manteniendo envío, multimedia, grupos, eco y parche de tablas nativas sin imports legacy ni efectos al cargar módulos.

Scope: `src/v2/adapters/evolution/**`, `tests/contract/evolution*.test.js`, este documento. Revisados `src/services/evolution.js`, `src/utils/whatsappText.js`, `src/integrations/evolutionNativeTables.js`, `scripts/patch-evolution-native-tables.cjs` y tests legacy asociados. No modificaciones a package/config/main/legacy/PROGRESS ni commits; no producción/red externa.

Factory explícita `createEvolutionAdapter(dependencies)` exportada de `index.js`: recibe `{client,instance,clock,echoGuard,io:{stat,readFile},history?,logger?,maxFileSizeMb?,maxDocumentSizeMb?,maxDownloadBytes?}`. El composition root construye/injecta todas las instancias y mantiene único dueño de history. La factory no abre archivos, conexiones ni timers; las operaciones explícitas usan las dependencias. No fallback a fs/environment reales.

`whatsappText.js` es port local completo del helper pure legacy: Markdown/LaTeX, código/Unicode, chunks balanceados, planning, native envelope, text canónico y fallback. No nueva capa ni provider: helper interno de presentación del adapter. `SendTextOptions` incorpora el puerto del núcleo y preserva delay/raw/maxLength; alias `delayMs` y quote estructural top-level en texto/media. El esquema legacy `sendNativeTable` no acepta quoted; no se amplió silenciosamente ese parche. Antes de exigir reply-to para tablas citadas, resolver composición/fallback de esa variante en Composer.

HTTP usa fetch nativo inyectable, auth apikey, base URL http(s) validada y paths locales; no redirects, respuestas stream con límite y timeout Clock. Timeout default60000ms y maxResponseBytes100MiB (configurable). No error retiene request/config/credenciales ni body raw del provider: response.status y data con códigos públicos allowlisted NATIVE_TABLE/INSTANCE y frases constantes para media expired/failure. Contracts afirman que cuerpos con PII/token no aparecen en JSON del error. Éxitos conservan data desconocido para consumidores; el límite de media valida tipo base64 antes de decodificar.

Retries legacy de poll/sticker/reacción/grupos/download usan Clock, dos reintentos/1500ms; 400/401/403/404 y MEDIA_TOO_LARGE no reintentan. Texto/media/voice/edit no reintentan POST incierto. Fallback native table solo tras rechazo comprobado antes de transmisión, sin echo; chunks/media aceptados se reflejan en partialDelivery/sentChunks/sentMedia. No se inventa messageId/fromMe ni se reenvía delivery incierto.

Media default MAX_FILE64MiB, documento mínimo200MiB como legacy; readFile revisa stat y bytes reales para crecimiento concurrente. Voice/sticker también se acotan por file limit. Download default64MiB, caller maxBytes validado y límite HTTP previo + decodificación; medios cifrados parciales sin mediaKey se hidratan por key. No descarga directa de URLs arbitrarias. IO debe ofrecer Buffer y metadata reales; los contracts usan fake IO. Memoria base64 se desvincula al terminar; no se invoca global.gc del proceso.

EchoGuard recibe `{clock,store:TtlStore,record?,ttlMs=300000,maxEntries=1000,namespace?}`. Cache TtlStore para IDs, entradas acotadas para pending/early echo, expiración y pruning por Clock. La callback record es el único dueño de historial para outbound texto/caption/native; Composer no debe registrar de nuevo esos efectos. Manual fromMe con texto igual después del ACK no se confunde con echo: necesita ID conocido, matching texto sirve solo mientras pending. Capacidad compartida de TtlStore no convierte ACK en fallo: IDs permanecen en la lista de entradas acotada hasta TTL, sin borrar sesiones ajenas; contract prueba esa situación. dispose limpia únicamente namespace de IDs propios.

NativeTables preserva validación64KiB/celdas3500/20headers/100rows, guards auth originales, instanceName, conexión/relay Baileys, error next sin retry tras posible relay. Patch puro fail-closed ante bundle diferente/parcial; idempotente y conserva viewOnce. modulePath admite un path absoluto seguro y default al destino operacional legacy del patch; actualizarlo al nuevo bundle depende del despliegue. Ninguna operación de parche se ejecutó en producción.

Tipos: CheckJs strict verde, datos HTTP públicos unknown; se mantienen anotaciones any locales en parsing de objetos dinámicos de Evolution, errores con partialDelivery y sobrecargas sendMedia legacy. Esas fronteras cuentan con validaciones de payload/metadata/base64 y tests; no se usan any para el puerto HTTP público ni para todos los inputs Messenger. La migración del schema completo de raw webhook corresponde al normalizador de Fase3.

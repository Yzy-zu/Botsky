# WO-009 / Fase 0 / Observador temporal de capturas reales

Objetivo: observar tráfico HTTP entrante real de `POST /webhook` y persistir únicamente envelopes anonimizados, sin cambiar el pipeline ni la configuración de Evolution.

Archivos permitidos: `scripts/refactor/capture-preload.cjs`, `tests/unit/refactor/capture-preload.test.js`, este documento. Ampliación autorizada por el maestro: `scripts/refactor/anonymize-webhook.cjs` y `tests/unit/refactor/anonymize-webhook.test.js` para conservar `send.message`. Insumos: anonimizador puro de WO-006. No se modificaron aplicación, fixtures existentes, `.env`, logs ni producción desde esta WO; no hay commits. La instalación operativa corresponde al maestro.

Activación temporal: cargar el archivo con `node --require /ruta/absoluta/capture-preload.cjs ...` y establecer explícitamente estas variables en el proceso de captura:

| Variable | Significado | Default |
|---|---|---|
| `REFRACTOR_CAPTURE_ENABLED` | Solo `1` o `true` activa observador | apagado |
| `REFRACTOR_CAPTURE_DIR` | Directorio absoluto dedicado para capturas | obligatorio al activar |
| `REFRACTOR_CAPTURE_LIMIT` | Máximo de envelopes aceptados | 50, máximo 1000 |
| `REFRACTOR_CAPTURE_DURATION` | Duración en **milisegundos** | 900000, máximo 3600000 |
| `REFRACTOR_CAPTURE_DEDUPE` | `1` o `true` conserva solo el primer envelope por combinación de categorías | apagado |
| `REFRACTOR_CAPTURE_BOT_ALIASES` | Alias confiables PN/LID obtenidos de metadata de Evolution; JSON array o lista separada por comas, máximo 16 JIDs | vacío |
| `REFRACTOR_CAPTURE_BOT_JID` | Identidad del bot solo para clasificar capturas | vacío; prioridad sobre `BOT_NUMBER` |

`BOT_NUMBER` sirve únicamente como fallback si ya está configurado. No es necesario cambiarlo: la variable dedicada evita alterar comportamiento del bot. No imprimir la identidad real al configurar ni al reportar resultados.

`installCapture(options)` no tiene efectos si `enabled:false`; importar el módulo no instala nada salvo activación explícita por env. Devuelve `active`, métricas agregadas `stats`, `flush()` para finalizar escrituras pendientes y `stop()` para retirar listeners propios y restaurar `http.Server.prototype.emit`. El preload habilitado publica ese controlador como `preloadController`. La instalación falla con diagnóstico genérico sin imprimir valores ni payloads; el proceso del bot sigue su arranque.

El wrapper de `http.Server.prototype.emit` escucha `data/end` de la request y delega inmediatamente al emisor previo con sus argumentos y retorno originales. No modifica bytes, listeners de la aplicación, response ni ACK. La captura de body añade observación al mismo stream consumido por Express; tests HTTP verifican que body y respuesta permanecen idénticos. El trabajo de parseo/anonimización es síncrono y acotado; la escritura se realiza asincrónicamente. No se promete latencia idéntica.

Solo captura `POST /webhook` con `event:messages.upsert` o `event:send.message`, `data` objeto y `key.remoteJid` string. Para `send.message` exige además `key.fromMe === true`; su nombre de evento se preserva en el envelope, nunca se reetiqueta como upsert. Descartes: JSON malformado, otros eventos, otros paths, body >1 MiB o concurrencia >8 requests observadas. Memoria raw acotada a 1 MiB por request y ocho requests por defecto; configuración programática permite reducirlos, con máximos 1 MiB/16. No usa headers ni loguea payloads. Los errores son contadores, sin textos originales. Al límite de count o deadline se deshabilita, elimina sus listeners y restaura el emisor, respetando un wrapper externo que haya reemplazado el suyo. El timer no mantiene vivo el proceso. Un límite alcanzado detiene capturas; hasta terminar de drenar las escrituras async puede haber menos archivos que `accepted`.

Formato persistido: `{capture:{provenance:"real-anonymized",source:"live-http",contentProvenance:"synthetic-replacements",categories:[...],botJid?:"JID sintético",botJids?:["alias sintéticos"]},webhook:{event,instance,data}}`. Directorio 0700 y archivos exclusivos 0600, nombres UUID+contador sin datos originales. Solo JSON ya anonimizados entran en la cola de escritura; nunca se persisten bytes raw, secretos, headers, URLs reales, claves de medios o textos personales. El anonimizador aplica whitelist y omite campos desconocidos.

Dedupe opcional: `installCapture({deduplicate:true})` o `REFRACTOR_CAPTURE_DEDUPE=true` evita llenar el límite con eventos repetidos de la misma combinación de categorías. Firma construida solo de vocabulario cerrado de categorías, sin texto, IDs ni datos personales. Los duplicados incrementan `stats.duplicates`, no `accepted`, y no se escriben; los IDs salientes se registran antes de deduplicar para conservar evidencia de citas posteriores. Se mantiene como máximo una firma por captura aceptada, acotada por `limit`; deadline termina la observación aunque siga recibiendo duplicados. Default apagado conserva la captura de todos los eventos.

Categorías: privado/grupo, LID, alternativa `participantAlt`, texto, mención estructural, mención al bot cuando comprobable, cita al bot/humano/desconocido, imagen/video/audio/documento/sticker/reacción/poll, `fromMe` y `outbound-notification` para `send.message`. Un outbound notification **no prueba** que Evolution también emita un eco `messages.upsert`: son tipos de evento distintos. `quote-bot` requiere participante que coincida con un alias confiable PN/LID o `stanzaId` de un mensaje `fromMe` observado previamente **en el mismo chat**, incluyendo `send.message`. La identidad PN se compara con normalización 521/52 solo para JIDs `@s.whatsapp.net`; LID se compara exacto, sin eliminar dispositivos ni convertir dígitos a teléfono. Caché saliente limitada a 500 IDs, sin persistencia raw y actualizada incluso para eventos deduplicados. `quote-human` exige participante de tipo PN/LID reconocido diferente de todos los alias y al menos un alias del bot confiable **del mismo dominio**: un LID se clasifica humano solo cuando se conoce un LID del bot; PN solo cuando se conoce PN del bot. Sin esa evidencia por dominio o con formato irreconocible queda `quote-unknown`. Un alias desconocido no concede mención/cita al bot. Nunca se decide por texto. La lista de alias debe venir de metadata confiable; no se aprende de una mención humana.

Si hay identidad configurada, `capture.botJids` contiene el conjunto de alias anonimizados mediante witnesses sintéticos en el mismo batch que el envelope, y `capture.botJid` prioriza un alias observado en quote/mention; ninguno contiene JIDs reales. Los witnesses no se persisten como supuestas capturas operativas: sirven solo para compartir el mapping del anonimizador. También se conserva la variante PN presente para que el JID sintético de metadata coincida con el del mensaje cuando hay formato 521/52.

Límites de evidencia: mapping reiniciado por envelope, por lo que los IDs/JIDs sintéticos de dos archivos independientes **no deben vincularse** como si compartieran cache. La categoría puede tener prueba saliente en memoria que no se refleja como relación cross-file. Alias telefónicos múltiples de la misma identidad dentro del mismo payload siguen siendo strings distintos para el anonimizador; revisar esos casos antes de componer escenarios. Los textos, captions y nombres de menú se sustituyen: requieren contenido ficticio equivalente para probar prefijos, selección o wake words. Bytes de medios y votos cifrados no se conservan. Las capturas no bastan para probar descargas ni contenido multimedia. La fuente `live-http` describe el mecanismo; los tests localhost de esta WO usan mensajes ficticios y **no acreditan tráfico real de WhatsApp**.

Antes de incorporar archivos: revisión manual de seguridad y cobertura; registrar procedencia `real-anonymized` separada de los contenidos sintéticos; quitar preload y variables temporales del proceso al finalizar y verificar salud del bot. Archivos de captura deben mantenerse fuera de producción/repositorio hasta revisión.
